# AI 持续任务验证

本轮在现有 AI 侧栏增加任务计划与连续推进，不增加独立工作台。

## 行为与边界

- 三种协议共用计划工具和已有执行服务；步骤数量上限 12，最多一个进行中步骤。
- 每次请求最多 32 轮模型调用。计划未完成却无工具收尾时最多追加两次临时续行提示；提示不作为用户消息存储。
- 未完成、用户拒绝和明确阻塞均保留暂停状态。继续任务恢复计划，已有防重复修改、主机身份复核和操作审批继续适用。
- 步骤完成由模型报告；不会把计划本身当作命令执行或独立验证证据。

## Windows 原生验证

精确识别本项目 `npm run dev` 启动的 `target/debug/transterm.exe`、当前 Vite 5188 页面与其进程树上的 WebView 调试端口。使用独立 portable 配置、回环 Provider 夹具和自建本地终端，不使用用户的模型密钥或远程主机。测试资源均已清理。

- Chat、Responses、Anthropic 每种协议均连续完成 13 轮任务，执行 9 条本地检查命令。半自动审批保留，计划最终完成；故意提前给出结论后自动继续。
- 计划未完成且模型持续收尾：恰好两次提醒后暂停，原始用户消息只有一条。
- 拒绝批次第一条修改命令：后续命令不执行，下一轮不再提供工具，未创建目标文件。
- 模型报告缺少用户输入：保留具体阻塞原因，不执行额外命令。
- 原生 React 组件验证草稿恢复、文件差异与独立审批、历史搜索和分支；步骤显示 1/3，继续按钮可用。四个内置主题在 320px 侧栏无横向溢出，减少动态效果设置正常，无 React 错误。

证据保存在本地 `.npm-cache/native-build/task-agent-native.json`、`task-agent-ui-native.json` 和同目录日志/截图中。
